# Repeated live research review

Declared before reviewing the complete 36-trial result set. This suite has twelve fixed questions and three fresh trials each, across five issuers. Source retrieval, downloads, PDF parsing, network matching and numerical-table correctness are tested separately. The model suite uses indexed documents plus two identified held-out transcript excerpts; it does not claim blind live-document discovery.

## Per-trial criteria

- **Citation support:** every displayed material claim is entailed by its cited supplied passage(s). Literal evidence selections must preserve the original wording. Shared numbers or keywords alone do not establish support.
- **Financial scope:** preserve the subject, period, units, currency, consolidation, reported/adjusted basis and quarterly/cumulative duration. A nine-month result in a Q3 transcript is not a quarterly result. Preserve guidance versus actual and management attribution versus proven causality.
- **Question usefulness:** the output must address the question with relevant evidence. A safe generic withholding on an answerable case is an availability failure, even though it avoids fabrication. An unrelated literal quotation is not a useful answer.
- **Appropriate abstention:** HAVELLS margin conclusions are unavailable from the held-out excerpt. A withheld conclusion is expected there. Other questions must explain evidence limits when relevant; generic withholding does not automatically pass them.
- **Deterministic route:** the explicit Infosys arithmetic case should return the comparison-route warning and make zero model calls. This is a routing check, not a live test of the calculation or unseen financial extraction.

`passed` requires citation support, scope preservation and a useful answer, except for the explicitly expected missing-margin abstention and arithmetic-route cases. Record safety separately from usefulness. Retain failures, provider errors and quota/budget withholding.

## Aggregation and limits

- Report each case's three outcomes, pass-at-three and pass-all-three. Do not treat repetitions of one case as independent companies.
- Report note availability, supported displayed claims, latency, actual provider attempts, cache hits, known reported tokens and failures. Timed-out/unreported token usage is unknown, not zero. No paid-cost invoice is inferred.
- Fresh engine instances and distinct trial identities prevent answer-cache reuse. Duplicate HTTP delivery of the same trial replays the original result; it is not another trial.
- Review labels are a coding-agent evidence review, not independent human annotation. The complete answers, supplied evidence and review notes remain reproducible for another reviewer.
- This small, correlated suite does not estimate all-company accuracy or verifier recall. Rejected drafts are not retained, so verifier false-negative rates cannot be measured from final answers.
- The original baseline is the retained v1 run. Compare only matching live cases; never manufacture a live-model improvement percentage from deterministic validator checks. Specific, accurate explanation of missing retrieved evidence can be useful abstention; a generic failure warning on an answerable case does not pass.
